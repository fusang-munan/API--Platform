# 北辰 0.27.3：探活记账、断连结算与对账口径

## 问题与根因

2026-11-23 的对账调查确认，本地 Token 长期小于北辰不是单一计数错误，而是四条独立缺口叠加：

1. **探活不进网关账本。** 自动探活直连北辰，单轮实测产生 17~26 笔计费请求；当天 80 笔北辰请求中有 54 笔是探活，占缓存 Token 的 55.6%、金额的 35.9%。学生网关没有对应调用，差额因此始终存在。
2. **客户端断开后丢账。** 客户端 45 秒超时离开后，上游仍可能在十几秒后完成计费；旧逻辑立即取消上游并丢弃用量。
3. **Token 分项缺失或矛盾时被补零。** 上游只报部分缓存写入子项、或普通输入/缓存写未分开时，旧逻辑用剩余量补齐，可能把矛盾数据当成完整用量扣款；另有大量请求只能进入待核。
4. **对账口径。** 已停用的 Key 仍按创建日一直要求每日同步，导致后续完整账日永久缺账；未匹配流水一次拉回全部历史，默认“总计”翻页第二页因截止时刻变化被服务端拒绝。

## 改动

### A · 探活独立流水

迁移 `0066_beichen_probe_usage.sql` 新建探活流水，每次尝试（含重试）先占一行再派发，记录状态码、错误码、四类 Token 和检查时间。健康组合 6 小时、异常组合 1 小时、每轮 32 笔、每日默认 500 笔，手动强制可跳过时间窗。冲突用量写 `probe_usage_conflict`，四类计数保持 NULL，不进入日汇总。

迁移 `0068_beichen_probe_usage_evidence.sql` 增加 `raw_usage`，冲突时保留上游原始用量对象，便于复查具体字段和值。

### B · 断连结算与终态证据

非流式 HTTP 请求在客户端断开后保留 15 秒上游尾读，宽限内收到完整终态仍正常结算；只收到开始事件则保留一次尝试、进入待核、不扣款。终态判定按协议收窄：Anthropic 认 `message_stop`/`stop_reason`，OpenAI Chat 认 `finish_reason`，Responses 认 `completed`/`incomplete`，Gemini 认 `finishReason`。`/v1/responses/compact` 与 embeddings 等非生成端点不再强制生成终态，避免正常响应被记为失败。

### C · 对账账日与分页

- 汇总和逐笔查询统一截止到北京时间次日 00:00，同一账日内游标稳定；未匹配流水改为服务端游标分页，每页最多 50 条，`总计`/`本月` 均可连续翻页。
- 迁移 `0067_beichen_credential_retired_at.sql` 增加独立 `retired_at`，手动停用和学校预配换 Key 都会记录；仅修改采价配置、分组或名称不再改写停用日。停用当天仍要求同步，停用后的账日不再要求，停用前历史保留。
- 有唯一认领但尚无回执明细的流水，现在显示“唯一认领 · 本地状态”；没有认领证据的行仍显示“未确认本地关联”。
- 教师端修复三处状态问题：切换账期后旧请求不再把新页面卡在加载中；翻页失败后的“重试本页”使用失败页游标；严格视图读取中或失败时不再显示“暂无未关联记录”。

### D · Token 归一化与金额唯一性

统一解析器核对 Anthropic 的 5 分钟/1 小时/写入总数三个字段，以及 `total_tokens = 普通输入 + 缓存读 + 缓存写 + 输出`。矛盾时保留已观察到的子项合计，`usage_state=partial`、`usage_reason=conflicting_cache_creation_counts`、进入待核、不扣款；只有父项与子项一致，或总量等式唯一推导且无矛盾时才使用写数。金额唯一可确定时即时结算。冲突时把 5 分钟、1 小时和写入总数的原始值写入 `pricing_detail`，供核账复查。

## 计费口径

本轮不改变学生扣费公式：上游标准价 × 当前 Key 分组倍率 × 1.10，积分按 100 积分 = 1 元折算。改动只阻止错误扣款和漏结算，并让待核记录可复查。

## 残余风险

- 探活已进入独立流水，但北辰逐笔归档没有保存 UA，学生未匹配清单仍可能包含探活收费；需要再用受控样本确认可核实的标记，才能自动从学生差额中剔除。
- `retired_at` 的历史值用迁移时的 `updated_at` 回填；若旧版本已改写该时间，无法还原真实停用日。同一 Key 多次启停目前只保留最后一次停用时间。
- 停用当天若在停用前没有完成同步，自动同步不再覆盖该 Key，该账日会持续显示缺账，而不是伪造完整。
- 15 秒尾读会让断连请求多占用一个后端连接和 goroutine；仅在客户端断开且可能已发出的非流式请求上启用。
- 分页已验证 201 条五页无重漏，未测量生产规模下大历史表的查询延迟。
