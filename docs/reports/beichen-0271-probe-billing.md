# 北辰 0.27.1：探活小时级刷新、粘性可用与全额结算

## 用户看到的问题

1. 上游只抖了一下，模型在列表里消失一整天；教师页的探活时间停在 00:54，早上点“重新探活”也不刷新。
2. 学生用量页出现大量“待核账、扣分 0”，大输入调用尤其明显，学校可能少收钱。
3. Gemini 渠道（哈吉米，group 5，上游 Key 12098）所有接口 403，已经无法服务任何模型。

## 改动

### 探活与可用性

自动探活从“当天只探一次”改为每小时一次。手动“重新探活”通过 requested_at 强制重探，不再被当天去重规则挡住；自动任务运行期间收到的手动请求会排队，不会被完成事件清掉。
只探测 Key 实际返回的目录行（catalog_source=key），不会再拿错误的 Key 去探别的模型（教师页 G3 不含 DeepSeek 的诊断行不再生成探活目标）。
网络错误、超时、408、429、5xx 最多重试两次（间隔 2 秒、4 秒）；400/401、凭据不可读等确定性失败直接记录。每条请求 8 秒上限，批次间续租。
新增 availability=degraded：最近 7 天内有过成功探活、但最新一次失败的模型不再判“维护中”，学生端和教师端显示“可用 · 探活异常”，保留“可能请求失败”的说明；/v1/models 默认仍列出它。
学生把 degraded 模型加入 Key 时返回 MODEL_DEGRADED 警告；学生 Key 页和模型广场都显示探活异常数量。

### 计费与待核账（对照 Sub2API）

按 Sub2API 普通文本计费方式：请求前保留准入预留；请求完成后只要拿到可信用量和有效价格，就按实际费用全额扣分，不再用单笔 1,000 积分上限或当前余额截断；费用可以把当月额度用超，下一笔在准入时拦截。旧调用如果已经记录了 student_cap_milli，继续按旧规则结算，避免补账改变历史。
Responses 明确以 max_output_tokens 结束的响应不再当作中断；HTTP JSON、SSE、WebSocket 三条路径一致处理。输入分类中某一类覆盖全部输入时，缺失的缓存类别补零，避免“总数齐全但缓存缺项”被误判。
待核仍保留给真正缺证据的情况：无法对齐发送记录、缺终帧用量、缓存分类冲突、价格/倍率缺失、模型不匹配、条件报价无法计算。待核显示 0 代表校内尚未扣分，临时预留已释放；有迟到完整用量或唯一匹配回执时可以补账。

### Gemini 渠道

迁移 0065 只做安全下线，不删除历史：按北辰 base_url + group_hint=5 / label=哈吉米 / upstream_key_id=12098 窄条件匹配，且供应商必须还有其它 active 凭据；命中后把凭据、目录和显式绑定置为 inactive。教师手动探测也会拒绝 inactive 凭据。

## 已知边界

探活表只保留每个 Key/模型/协议的最新一行；如果历史成功已被失败覆盖，last_passed_at 只能等下一次成功探活恢复（迁移只回填当前仍成功的行）。
截图里的三笔历史待核不能仅凭两个总数补扣，仍需从生产账本读取 review_reason、缺失字段、价格与回执匹配状态。
0065 在生产实际命中数尚未核验；如果标签/分组与预期不同，渠道会保持 active，需要教师页确认后再处理。
