# 0.17.0 实施契约（冻结）

本文件由总控冻结。所有并行工作流以此为接口与行为基准；如需改动，先回报总控。

## 发布规则

- 分支 `codex/beichen-017-all`，基线 `origin/main` `ad8ce5e`（0.16.0）。
- 全版本只提一个 PR、只合并一次、只部署一次；版本号 `VERSION` 改为 `0.17.0`。
- 中间不发布、不改线上环境；验证全部走本地测试与临时 PostgreSQL。
- 不做真实模型调用；不重录、不打印任何北辰 Key 或 Cookie。

## 口径

- 北辰官网价单位是「元 / 百万 Token」。展示时同时给出积分：**1 元 = 100 积分**，即官网价 × 100。
- 学生实价 = 官网价 × 学校倍率，再 × 100 显示为积分；倍率以行内 `effective_multiplier_text` 为准。
- 金额一律十进制字符串或整数微单位，禁止浮点。Token 用整数。
- 「待核」指上游未回报或价格无法判定，必须单列，不能混进 0。

## 后端 JSON 契约

### 1. 概览 `GET /api/v1/teacher/providers/:provider_id/beichen`

新增顶层 `credentials[]`：

```json
{
  "credential_id": "uuid",
  "label": "渠道名",
  "status": "active",
  "catalog_last_success": "RFC3339|null",
  "prices_last_success": "RFC3339|null",
  "billing_last_success": "RFC3339|null",
  "usage_last_success": "RFC3339|null",
  "last_error": "string|null",
  "model_count": 12,
  "priced_model_count": 10
}
```

`model_catalog[]` 新增字段：

- `key_count`：该模型有报价或路由的 Key 数。
- `route_count`：候选线路数（协议 × Key）。
- `ready_count`：已发布就绪线路数。
- `price_state`：`confirmed` | `conditional` | `manual` | `missing` | `mixed`。
- `blockers[]`：`{ "code": "...", "message": "..." }`，code 取值 `not_configured` / `no_ready_route` / `missing_price` / `conditional_price` / `sync_failed`。
- `activation`：`active` | `ready` | `blocked`。

### 2. 模型用量（复用既有接口）

`GET /api/v1/teacher/model-usage?range=month&provider_id=:id`（现有接口，前端已有 `modelUsage`）。

在 `totals`、`models[]`、`students[]` 上补齐：

- `cache_hit_rate`：0–1 的数字或 `null`（无缓存数据时为 null）。
- `tokens_missing`：整数，待核或上游未回报的 Token。
- `completeness`：`complete` | `partial` | `missing`。
- 阶段 2 追加 `school_absorbed_credits`。

### 3. 手动定价 `PATCH /api/v1/teacher/providers/:provider_id/beichen/models/price`

请求新增可选：

```json
{ "scope": "all" | "credentials", "credential_ids": ["uuid"] }
```

响应新增 `applied_credential_ids: ["uuid"]`，必须等于服务端实际写入的范围。缺省 `scope` 视为 `all`，保持旧行为。

### 4. 对账 `GET /api/v1/teacher/providers/:provider_id/beichen/reconciliation`

- `models[]`、`keys[]` 新增 `school_absorbed_credits`（十进制字符串）与 `completeness`。
- `coverage` 新增 `verified_matched_calls`（整数）与 `coverage_kind`：`full` | `partial` | `none`。
- `match_status` 语义改为「两边均有记录」；页面文案不得再写「已匹配」。

### 5. 阶段 2 计费（同版本内落地）

- `gateway_calls` 新增：`reasoning_effort`、`cache_ttl_seconds`、`price_tier`、`price_snapshot`(jsonb)、`pricing_detail`(jsonb)、`actual_micros`、`student_micros`、`school_micros`、`truncated_quota`(bool)。
- 学生月桶只加 `student_micros`；`school_micros` 单列，用于对账。
- 迁移编号由总控预留，全版本只有一个迁移文件，仅 H 工作流可改。

## 行为规则

- 「一键启用」：前端调用既有 `models/enable-batch`（每批 ≤200），只提交 `activation === "ready"` 的模型；逐项展示结果，失败可重试。
- 价格抽屉：保存前必须列出服务端将改动的全部 Key 与影响行数；保存后按 `applied_credential_ids` 核对并提示。
- 拨积分：「补足已用」只向上补，永不低于当前额度；保存前展示变更前后对比；待核单列。
- 学生余额不为负；单笔上限 1000 积分，超出记学校承担；余额 > 0 时仍允许最后一笔，按剩余额度预算输出。
- 可预算模型注入 `max_output_tokens`；上游超预算强制断开并标 `truncated_quota`。
