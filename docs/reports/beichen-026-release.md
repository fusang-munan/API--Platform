# 北辰 0.26.0 发布记录

0.26.0 把北辰模型管理的主表收敛到四把渠道 Key 当前 `GET /v1/models` 的结果，并统一价格展示与结算口径。

## 目标

- 主表只显示四把 Key 当前探测到的模型；官网目录里的其它分组和仅官网可见的型号单独计数，不进主表。
- 每个模型只有一张价格表：五列（输入、输出、缓存写入 5m、缓存写入 1h、缓存读取）两排（上游基础价、学生实价），不再并列展示其它分组。
- 账号倍率优先：`group_rate` 只作展示，`account_rate` 用于结算。
- 分组 16 没有自己的官网价表时，用公开官网同名模型基础价乘 0.60。
- 历史流水反推价只作审计，不自动扣费。

## 迁移 0061

`0061_provider_catalog_source.sql` 给 `provider_model_catalog` 增加非空 `catalog_source`，默认 `key`；把 `raw_entry->>'source' = 'beichen_website_group'` 的旧行回填为 `website`。只有 `key` 来源计入当前 Key 覆盖和教师页探活结论。

## 上线后

- 在「模型管理 → 北辰」对四把 Key 逐把执行重扫或核对，强制读取当前 `/v1/models`。
- 刷新后确认四把 Key 的目录时间均为当前时间，目录错误为空；旧官网目录行不提供 Key 覆盖。

## 验收

- 四把 Key 的当前模型数为 5、3、2、0，主表合并后 10 个模型。
- 分组 16 的两款 Claude 使用公开官网同名模型基础价，学生实价按 0.60 × 1.10 计算；页面不再出现其它分组的价格列。
- 只有反推价的调用保持待核，原因 `derived_price_requires_review`，不产生学生扣分。

## 迁移 0062

0062_expire_pre_026_prices.sql 把旧倍率和旧面板快照的有效期截到迁移时刻，避免升级后到首次重新核实之间继续用旧的 0.15/0.24/0.10 报价；历史调用仍按派发时间查当时有效的价格。升级后到首次成功同步前，新调用可能进入待核账，首次同步成功后恢复。

上线后请等待首次计费/价格同步完成，再观察学生调用；不要只看目录刷新完成。
## 剩余风险

- Group 16 依赖同一把 Key 的 /keys 分组和 /v1/sub2api/billing 两次读取一致；若两次读取之间换组，下一次同步会纠正，极端情况下该次报价进入待核。
- 后端按 Key 所属平台筛选公开基础价；教师页跨组回退只看 price_scope=platform。当前四把 Key 的型号名没有跨平台重名，后续新增同名型号时需要补平台字段到 Key 清单。
- 通用「重建绑定」仍以目录和协议为主；当前四把 Key 的模型都有正式基础价，未出现只能待核的线路。
