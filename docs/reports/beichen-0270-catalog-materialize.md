# 北辰 0.27.0：目录定时物化与缺价建议

## 问题

北辰 Key 目录本身由计费任务每 15 分钟刷新，但平台在非重置同步时对北辰直接跳过物化：新探测到的模型只停留在 provider_model_catalog，不会生成 models 和绑定，教师页看不到候选，学生更无法选择。
批量启用遇到没有官网报价的模型时只返回 no_price，没有把已有的历史流水反推价带回响应，教师无法据此补价后重试。

## 改动

新增目录物化 worker：服务启动时执行一次，之后每 10 分钟运行。只处理启用中的北辰供应商，按渠道执行无损物化（reset=false）并重建线路，不重置教师已设置的价格、is_common 和启用状态。
批量启用跳过 no_price 时返回 suggested_rates：取该线路最新一笔 derived_from_usage 上游价，包含输入、输出、缓存读写和观察时间。官网价存在时仍以官网价为准。
不修改 /v1/models 口径、计费规则和数据库结构。

## 验证

go build ./...、go vet ./...、go test ./... -count=1 通过；本机未配置 NEBULA_TEST_POSTGRES，Postgres 用例按原样跳过。
新增 sqlmock 用例覆盖反推价建议的两条路径：命中最新观察、无观察时返回空。
线上验收：部署后教师页对四把 Key 重扫并批量启用探测到的模型，学生广场应从 5 个恢复为 10 个；pp2 的 /v1/models 应同步出现新模型。

## 已知边界

Gemini 渠道仍为上游 403 GROUP_NOT_ALLOWED，在分组恢复前不会出现在任何 Key 目录。
CC2（group 16）没有官网报价，启用 Claude 系模型需要教师按反推价建议设置手动价。
