# 待核账只读审计

`cmd/pending-audit` 用来判断待核账里有多少是“拆分不影响金额”、多少是“金额误差很小可以自动结”、多少必须靠估计或人工。它只读数据库，不扣款、不改账。

## 运行

```bash
DATABASE_URL='postgres://只读用户:密码@主机:5432/数据库?sslmode=require' \
  go run ./cmd/pending-audit -limit 2000 -out pending-audit.json
```

可选参数：

- `-threshold 0.001`：允许自动结算的最大金额误差，单位元。
- `-relative 0.01`：允许自动结算的相对误差，0.01 表示 1%。
- `-limit 2000`：最多读取多少笔待核。

建议用只读账号，连接串加 `default_transaction_read_only=on`；程序本身也在只读事务里查询。

## 分类口径

- `exact`：所有计费分项已知，或缺失分项的单价相同，金额唯一，可直接结算。
- `narrow`：缺失 Token 的最坏金额误差不超过 `threshold` 或 `relative`，可按保守值自动结算并标记低置信度。
- `wide`：金额误差较大，需要每学生历史估计或人工核验。
- `unknown`：缺少输入/输出总量、总量矛盾、协议未知或拿不到价格，无法给出上界。

金额按上游单价计算，1 个上游单位约等于 1 元；学生倍率和学校加价在结算层再加。`max_error_yuan` 是“把缺失 Token 全部算到最贵分项”和“全部算到最便宜分项”的差额上界，不是实际扣款。

## 当前限制

- 没有价格分项的待核会归为 `unknown`，需要价格快照或手动价。
- 输出只做金额区间判断，不会替待核选拆分；真正的自动结算算法要在下一步实现。
- 生产数据量下建议先 `-limit` 分批跑，确认查询耗时。
